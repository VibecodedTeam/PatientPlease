# Real Case Seeding Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace `seed.ts`'s synthetic, round-robin-assigned case data with 31 real, translated, medically-mapped cases, each with a correctly categorized set of documents and a matching image reference.

**Architecture:** A new typed data file (`src/backend/src/db/data/realCases.ts`) holds the authored case content. A small pure resolver (`src/backend/src/db/caseSeedRefs.ts`) maps each case's diagnosis/treatment/examination codes to real catalog row IDs, replacing the current `i % length` round-robin. `seed.ts`'s per-case loop is rewritten to consume this data directly. Images are frontend static assets under `src/frontend/public/cases/`.

**Tech Stack:** TypeScript, Prisma, Jest (`ts-jest`), Fastify (unaffected by this change).

## Global Constraints

- Backend is TypeScript only (`src/backend/src/**/*.ts`) — no `.js` source.
- No new Diagnosis/Treatment catalog rows — every case maps to the closest existing `Diagnosis.code`/`Treatment.code` from the 25/25 already in `seed.ts`.
- Citations/sourcing links are never stored in the database — they live in `docs/game-design/case-sourcing-notes.md`.
- Where the source case doesn't state a fact, the corresponding field is `null`, never a fabricated placeholder value.
- No backend image-serving route — images are referenced as frontend static paths (`/cases/<file>`), matching the existing `src/frontend/public/melanoma/` precedent.
- New logic (the resolver) gets a failing test first, per this repo's TDD rule. Hand-authored case content is not "logic" and is not test-driven in the red/green sense — it's validated by the static-integrity test in Task 4.
- Four cases (16, 23, 26, 29) had no stated final diagnosis in the source text (one was cut off mid-sentence). Per explicit user instruction, their conclusions were generated by Claude to complete the case, and each carries a `sourceNote` saying so — this is not silently hidden. Two further cases carry a `sourceNote` for a narrower reason — a diagnosis inferred from clinical evidence rather than a literal stated conclusion: case 28 (a specific, named dermoscopy sign) and case 9 (an ABCDE criteria assessment, with no word for the diagnosis anywhere in the source text, unlike cases 8/14/15 which do state "melanoma" in prose even without a bracketed tag). `sourceNote` is `null` for every other case.

- [ ] **Step 4: Write `resolveCaseSeedRefs`**

Create `src/backend/src/db/caseSeedRefs.ts`:

```ts
import type { RealCaseSeed } from './data/realCases.js';

export type CaseSeedCatalogs = {
  diagnoses: Array<{ id: string; code: string }>;
  treatments: Array<{ id: string; code: string }>;
  shopItems: Array<{ id: string; sku: string }>;
};

export type ResolvedCaseSeedRefs = {
  diagnosisId: string;
  treatmentId: string | null;
  examinationShopItemId: string;
};

export function resolveCaseSeedRefs(
  realCase: RealCaseSeed,
  catalogs: CaseSeedCatalogs,
): ResolvedCaseSeedRefs {
  const diagnosis = catalogs.diagnoses.find((d) => d.code === realCase.diagnosisCode);
  if (!diagnosis) {
    throw new Error(
      `Unknown diagnosisCode "${realCase.diagnosisCode}" for patient "${realCase.patientName}"`,
    );
  }

  let treatmentId: string | null = null;
  if (realCase.treatmentCode !== null) {
    const treatment = catalogs.treatments.find((t) => t.code === realCase.treatmentCode);
    if (!treatment) {
      throw new Error(
        `Unknown treatmentCode "${realCase.treatmentCode}" for patient "${realCase.patientName}"`,
      );
    }
    treatmentId = treatment.id;
  }

  const examinationItem = catalogs.shopItems.find((item) => item.sku === realCase.examinationSku);
  if (!examinationItem) {
    throw new Error(
      `Unknown examinationSku "${realCase.examinationSku}" for patient "${realCase.patientName}"`,
    );
  }

  return {
    diagnosisId: diagnosis.id,
    treatmentId,
    examinationShopItemId: examinationItem.id,
  };
}
```

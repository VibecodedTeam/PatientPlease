Generated by walking `REAL_CASES` (`src/backend/src/db/data/realCases.ts`) and
`FICTIONAL_CASES` (`src/backend/src/db/data/fictionalCases.ts`) directly — all

## 1. Where each piece of on-screen text comes from

The desk document panel (`Table` → `TabElem` → three `Information_N` cards)
pulls from a case's `documents` array by `type`:

| Card | Component | Reads document type(s) | Fallback when missing |
|---|---|---|---|
| "Patient Information" | `Information_1.jsx` | N/A — reads `patient.name`/`age`/`sex`/`occupation` directly | Shows "Jane Doe" / age 42 / "Pending clinical note" ×3 — **only during loading**, never for a loaded case |
| "General Patient Story" | `Information_2.jsx` | Any of `DISEASE_HISTORY`, `UV_EXPOSURE_HISTORY`, `FAMILY_HISTORY`, `WEATHER_HISTORY` | **"Lorem ipsum dolor sit amet..."** placeholder if the case has *none* of those four document types |
| "Clinical Symptoms" | `Information_3.jsx` | `CLINICAL_SYMPTOMS` | A hardcoded Itching/Redness/Swelling placeholder table if missing — **not currently a risk**, every one of the 61 cases has a `CLINICAL_SYMPTOMS` document |
| Examination results (in `Information_2`'s history sweep, `EXAMINATION_RESULTS` type) | same as above | `EXAMINATION_RESULTS` | Only appears at all once the *correct* exam has been successfully ordered — see §2 |

**FIXED (was: the Lorem Ipsum fallback).** All 31 cases that previously had
only a `CLINICAL_SYMPTOMS` document (and so fell back to placeholder Latin
text in the "General Patient Story" card) now have exactly one added history
document — `DISEASE_HISTORY`, `UV_EXPOSURE_HISTORY`, or `FAMILY_HISTORY`,
whichever fit that patient's profile best. Verified: `pnpm --filter backend
test` (363/363 passing) and re-running the same doc-type sweep against
`REAL_CASES`/`FICTIONAL_CASES` now returns zero cases missing a history
document. The DB has been reseeded with this content — no further action
needed here before the demo.

Two fixes, not mutually exclusive: (a) author a short `DISEASE_HISTORY` (or
whichever fits) document for each of these 31 cases, or (b) change
`Information_2.jsx` to render nothing/a neutral "No additional history on
file" line instead of Lorem Ipsum when no history document exists. (b) is the
faster pre-demo fix; (a) is the more complete one.

## 2. Which examination gives a result, per case

Every case has exactly **one** examination wired to succeed — the one
matching its `examinationSku`. Ordering any *other* examination on that case
always fails: no findings are shown, the player is charged a money penalty,
and the day clock is docked for the exam's time cost, with zero feedback text
explaining why (`orderExamination` in `src/backend/src/services/examination.ts`
only matches on exact `shopItemId`; a mismatch just silently records
`isSuccessful: false`). **Before the demo, make sure the demo account owns
all 5 examination items from the night shop** — `orderExamination` throws if
the shop item isn't owned yet, so a case needing an exam you haven't bought
is simply unusable until you buy it.

examination SKUs:

## 4. Full case briefs — worked examples for image generation

Five representative cases, pulled straight from `realCases.ts`/
`fictionalCases.ts`, with all their text in one place plus a ready-to-use
English prompt built from that text. Use these as a template: the same
"translate clinical description → visual descriptors → prompt" process
applies to any of the other 56 cases using their own `bodyRegion` +
`examinationFindings` + `CLINICAL_SYMPTOMS` fields.

---

**Case-03 — Robert Sadowski, 39M, melanoma (REAL)**
- Region: back. Correct exam: Punch Biopsy.
- Symptoms: a mole on the back began bleeding after showering and toweling
  off; covered with multiple small blisters, noticeably larger than his other
  moles, with dark patches; enlarging over time; recently started to itch.
- Exam findings: biopsy confirms melanoma; excised with a safety margin.

> Prompt: *"Clinical dermatology photograph, close-up macro shot of an
> irregular pigmented skin lesion on a middle-aged man's upper back —
> asymmetric shape, dark brown-to-black patches, uneven jagged border,
> slightly raised surface with small blister-like areas, a couple of smaller
> ordinary-looking moles nearby for scale, neutral clinical lighting on bare
> skin, plain background, high detail, medical reference photo style, no
> text, no watermark."*

**Case-10 — Marcin Krupa, 50M, basal-cell-carcinoma (REAL)**

## 5. How to get case-specific, realistic images

Two real options, not mutually exclusive:

**Option A — real licensed dermatology photo archives (recommended for
melanoma/cancer cases).** This project already has precedent for this:
`src/frontend/src/components/MelanomaImagePopup/internal/melanomaImages.js`
pulls real images from the **ISIC Archive** (isic-archive.com), a public
dermoscopic-image research archive used for the ISIC skin-lesion challenge —
those files are stored under `public/melanoma/`. You can browse the archive
directly and download images filtered by diagnosis (melanoma, basal cell
carcinoma, nevus, etc.) the same way that popup's images were sourced, which
is more medically accurate than anything AI-generated. For non-cancer
inflammatory/infectious cases (psoriasis, eczema, impetigo, etc.), DermNet NZ
and the HAM10000 dataset (Harvard Dataverse) are the equivalent public
references — check each image's specific license before using it, since
terms vary per-image/per-dataset (research-only vs. broader reuse).

**Option B — AI image generation, prompt-per-case.** Use the template above:
region + visual descriptors pulled straight from the case's
`examinationFindings`/`CLINICAL_SYMPTOMS` text, phrased as neutral clinical
photography, explicitly avoiding the diagnosis *label* itself in the prompt
(describe what it looks like, not what it's called — some generators are
more permissive that way). A photorealistic-capable model (Stable Diffusion
XL/Flux run locally via ComfyUI/Automatic1111, or a hosted endpoint like
Replicate) gives the most control and no per-image content-policy friction;
DALL-E 3/Midjourney are easier to use but will sometimes refuse graphic
descriptions and tend to render skin conditions more "generic-rash-looking"
than medically distinct — expect to iterate on wording, and treat the result
as illustrative rather than clinically precise. Either way, generate at
`case-XX.png`'s exact filename and drop it straight into
`src/frontend/public/cases/`, matching the pattern already documented in
`MANIFEST.md` — no code change needed.
